# JevChess

Express + EJS + vanilla JavaScript 기반 체스 실험입니다. 사람은 White,
JEV Choice API는 Black의 합법 수 중 하나를 선택합니다.

## 버전별 실험: V1 → V2

현재 실행되는 코드는 **V2**입니다. 아래 V1은 이전 구현의 비교 기준이며,
현재 앱에 V1/V2 전환 기능이나 비교 실행 기능이 있는 것은 아닙니다.

### V1 — 현재 상태를 보고 수 선택

```text
현재 FEN + 전체 legal moves → JEV Choice → 선택 검증 → 원본에 적용
```

V1의 목적은 JEV가 서버에서 제공한 합법 수 중 하나를 직접 선택하는 전체 흐름을
확인하는 것이었습니다. 각 후보에는 ID, SAN, 출발·도착 칸, 프로모션 정보만 담았습니다.
후보를 적용한 뒤의 보드는 별도로 계산해 보내지 않아, 수의 결과는 JEV가 추론해야 했습니다.

V1도 실제 JEV API 연결 후에는 후보 확률과 confidence를 받았습니다.
따라서 **실제 API 연결이나 확률 표시 자체가 V2의 새 기능은 아닙니다.**
그보다 앞선 초기 mock 단계는 합법 수를 균등 랜덤으로 선택하던 동작 검증용 구현입니다.
이 문서에서 V1은 mock이 아닌, 실제 JEV에 현재 FEN과 합법 수를 보내던 버전을 뜻합니다.

### V2 — 후보를 적용한 결과 상태까지 보고 선택

```text
현재 FEN + 전체 legal moves
  → 후보마다 독립 복제 상태에 한 수 적용
  → resultingFen + 규칙 기반 features 계산
  → JEV가 결과 상태들을 비교하고 선택
  → 선택 검증 → 원본에 적용
```

V2의 실험 질문은 **“각 수의 결과 상태를 명시적으로 제공하면 JEV의 선택이 나아지는가?”**입니다.
chess.js는 결과 상태와 규칙상 사실을 계산하고, 어느 수가 더 좋은지는 JEV가 판단합니다.

### V1과 V2 비교

| 비교 항목 | V1 | V2 |
| --- | --- | --- |
| 현재 상태 | 현재 FEN | 현재 FEN 유지 |
| 후보 기본 정보 | ID, SAN, 출발·도착 칸, 프로모션 | 동일 |
| 후보별 결과 보드 | 제공하지 않음 | `resultingFen` 제공 |
| 후보별 특징 | 별도 결과 특징 없음 | 잡기, 잡힌 기물, 체크, 프로모션, 캐슬링 |
| 결과 상태의 추가 정보 | 제공하지 않음 | 상대 합법 수 개수, 상대 체크, 게임 종료 여부 |
| JEV 판단 지침 | 현재 위치에서 가장 좋은 수 선택 | 현재 수를 두는 쪽의 관점에서 결과 상태와 전술적 결과 비교 |
| 서버의 후보 분석 | 없음 | 후보별 독립 복제, 기보 이력 보존, 한 수 적용 |
| 화면 | 선택된 수, 확률 JSON과 confidence, 3초 미리보기 | 기존 표시 유지 + 결과 FEN·특징·별도 confidence 표시 |
| 오류 처리 | API·선택 오류 시 `jev_error` | 기존 정책 + 후보 분석 실패 시 전체 턴 실패 |
| 계산·입력량 | 후보 기본 정보만 처리·전송 | 후보별 복제·규칙 계산, API 입력 토큰 증가 |
| 최종 결정 | JEV | JEV 유지 |

### V2에서 개선된 점과 아직 확인할 점

**구현상 개선된 점**

- **입력 정보가 구체적입니다.** JEV는 현재 보드에서 각 수의 결과를 모두 추론하는 대신,
  서버가 계산한 결과 FEN과 체크·잡기 같은 사실을 함께 받아 비교합니다.
- **선택 결과를 관찰하기 쉽습니다.** 화면에서 선택된 후보의 확률과 실제 결과 상태를 함께 볼 수 있습니다.
- **분석이 원본 게임에 영향을 주지 않습니다.** 후보마다 별도 인스턴스를 사용하고 기보 이력도 보존합니다.
- **분석 실패를 숨기지 않습니다.** 잘못된 후보를 조용히 제거하지 않고 해당 턴을 오류로 처리합니다.

**아직 실험으로 확인할 점**

- 실제로 더 좋은 수를 선택하는지, 실수 빈도나 대국 결과가 개선되는지는 아직 측정하지 않았습니다.
- 자동 테스트 통과는 규칙 계산과 데이터 전달의 정확성을 확인한 것이며 기력 향상의 증거는 아닙니다.
- 더 많은 정보가 항상 더 좋은 선택을 보장하지 않으며, 입력 토큰과 서버 계산량은 늘어납니다.
- probability와 confidence는 모델 응답 값이며, 높은 값이 높은 체스 승률이나 좋은 수를 보장하지 않습니다.

Stockfish, material/position 평가 함수, 상대 최선 응수 탐색, minimax는 두 버전 모두 사용하지 않습니다.
V2의 상대 합법 수 개수는 결과 보드에서 가능한 수를 세는 값이며, 그 응수를 적용하는 2-ply 탐색이 아닙니다.

### 비교 실험을 할 때

같은 포지션과 같은 전체 후보 집합을 준비하고 모델 버전을 고정한 뒤,
V1 입력과 V2 입력으로 선택한 수·확률·confidence·응답 시간·입력 토큰을 나란히 기록하면 됩니다.
체크메이트 기회, 즉시 무승부가 되는 수, 잡기·캐슬링·프로모션이 있는 포지션부터
비교하면 입력 차이가 선택에 미치는 영향을 관찰하기 쉽습니다.
이는 후속 비교 방법이며, 자동 비교 도구나 기력 개선 결과는 아직 포함하지 않습니다.

## 실행

Node.js 20.12 이상이 필요합니다.

```sh
npm install
npm start
```

http://localhost:3000 에 접속합니다. 자동 재시작은 `npm run dev`입니다.
프로젝트 루트의 `.env`를 서버 시작 시 읽습니다. 기존 파일을 덮어쓰지 말고 다음 변수를 설정합니다.

```dotenv
JEV_KEY=발급받은_키
JEV_MODEL=jev-latest
PORT=3000
```

키는 브라우저에 전달하지 않습니다. `.env`는 Git 제외 대상입니다.
키 변경 후 서버를 재시작합니다. 키가 없으면 mock으로 대체하지 않고 오류를 표시합니다.

## 현재 게임 흐름 (V2)

1. 백색 말과 이동할 칸을 클릭합니다. 프로모션은 우측에서 선택합니다.
2. 서버가 버전·차례·합법성을 검증하고 사람의 수를 적용합니다.
3. 게임이 끝나지 않았다면 각 합법 수를 독립적인 복제 상태에 적용해 결과 FEN과 특징을 계산하고 JEV에 전달합니다.
4. JEV의 선택을 다시 검증하고 적용합니다.
5. 우측 JSON에 선택된 수, 응답 모델, confidence, 후보별 probability를 표시합니다. 선택된 후보의 결과 FEN과 특징도 표시합니다.
6. 사람의 이동까지 적용된 보드를 3초간 보여준 뒤 JEV 이동을 표시합니다.
   서버 상태는 이미 확정되어 있으며, 이 시간에는 이동과 New Game이 잠깁니다.
7. JSON은 이동 후에도 남고 다음 JEV 응답 때 갱신됩니다.

체크메이트, 스테일메이트, 기물 부족, 3회 반복, 50수 규칙을 처리합니다.
반복·50수 무승부는 별도 청구 없이 자동 종료합니다.
게임 ID는 sessionStorage, 게임과 기보 이력은 서버 메모리에 있습니다.
같은 탭에서 새로고침하면 복구되지만 서버 재시작 시 게임은 사라집니다.

## 실제 JEV 연결

`services/jevService.js`의 `selectMove({ fen, legalMoves })`에서 호출합니다.

- 제공자: JevTypeSafeAI의 hosted API (TypeSafe 공식 API와 별개의 서비스)
- 주소: `POST https://jevtypesafeai.com/api/v1/decide`
- 인증: `Authorization: Bearer <JEV_KEY>`
- 질문: `questions.move.type = "choice"`
- 후보: `criteria`의 키에 이동 ID, 값에 SAN, 출발·도착 칸, resultingFen, features
- 모델 출력: `answers.move.choice`, `probabilities`, `confidence`
- 내부 결과: `{ selectedMoveId, candidates, model, confidence }`

출력 패널은 API 응답을 위 내부 포맷으로 정리한 JSON입니다. SAN은 서버가 생성합니다.
확률은 API가 반환한 수치를 그대로 사용하며 무작위 숫자나 균등 확률로 대체하지 않습니다.
이는 질문의 후보에 대한 모델의 분포로, 체스 승률이나 엔진 평가값이 아닙니다.
confidence는 후보 확률과 구분하여 표시합니다.

후보 확률을 표시하려면 모든 합법 수가 중복 없이 포함되고 각 값이 0~1,
합계가 1이어야 합니다(허용 오차 0.000001). 확률 누락·오류 시 유효한 수는
적용하되 확률을 표시하지 않고 안내합니다.

문서: https://www.jevtypesafeai.com/typesafe/docs

## 오류와 재시도

요청당 제한은 15초입니다. 인증·잔액·호출 한도·연결·JSON·선택 오류를 처리합니다.
실패하면 `jev_error` 상태에서 사람의 수를 유지하고 `JEV 다시 요청` 버튼을 표시합니다.
재시도는 Black 턴만 다시 호출합니다. 유료 호출이 반복되지 않도록 자동 재시도와
랜덤 fallback은 없습니다. 실제 플레이와 수동 재시도는 API 사용량을 발생시킵니다.
통신 결과가 불확실할 때 브라우저는 수를 재전송하지 않고 게임 상태를 조회합니다.

## API

| 요청 | 역할 |
| --- | --- |
| `GET /` | EJS 페이지 |
| `POST /api/games` | 새 게임 생성 (201) |
| `GET /api/games/:gameId` | 현재 상태 |
| `POST /api/games/:gameId/moves` | 사람 이동 + JEV 턴 |
| `POST /api/games/:gameId/jev-retry` | 실패한 JEV 턴 재시도 |

이동 본문: `{"version":0,"move":{"from":"e2","to":"e4"}}`.
프로모션일 때 move에 `"promotion":"q"` 등을 추가합니다.
재시도 본문은 현재 `version`을 담습니다.
JEV 실패는 502와 최신 게임 스냅샷, 충돌은 409, 불법 수는 422,
잘못된 입력은 400, 없는 게임은 404입니다.

## 파일과 테스트

- `app.js`: 환경변수 로드, Express와 EJS 설정
- `routes/gameRoutes.js`: 페이지·게임 API
- `services/chessService.js`: 상태·규칙·후보별 결과 분석·응답 검증·턴 진행
- `services/jevService.js`: 실제 JEV API 호출과 오류 변환
- `views/index.ejs`, `public/js/game.js`, `public/css/style.css`: 화면
- `.env.example`: 비밀값 없는 설정 예시
- `test/chessService.test.js`, `test/jevService.test.js`: 핵심 동작과 API 계약 검증

`npm test`는 테스트 응답을 주입하므로 실제 API와 키를 사용하지 않으며 비용이 없습니다.

DB, 로그인, WebSocket, Stockfish, Undo, rate limiting, Origin 처리,
게임 만료 cleanup은 포함하지 않습니다. 단일 서버 프로세스용이며,
이전 게임은 서버 재시작까지 메모리에 남습니다.

## V2 후보 분석 상세

`analyzeLegalMoves(chess)`는 모든 합법 수에 대해 별도의 chess.js 인스턴스를 만듭니다.
시작 FEN과 기존 기보를 재생해 반복 이력도 보존한 뒤 후보 수 하나만 적용합니다.
원본에는 후보 수를 적용하거나 undo하지 않습니다. 상대의 응수는 적용하지 않습니다.

각 후보에는 `resultingFen`과 다음 `features`가 추가됩니다.

- `capture`, `capturedPiece` (p/n/b/r/q 또는 null, 앙파상 포함)
- `givesCheck`, `isPromotion`, `isCastle`
- `resultingLegalMoveCount`: 결과 상태에서 상대의 합법 수 개수
- `opponentInCheck`, `gameOverAfterMove`

종료 여부는 승리 점수가 아닙니다. 무승부도 true이며 반복 이력을 반영합니다.
어느 한 후보라도 분석에 실패하면 전체 턴을 `jev_error`로 처리합니다.
실패한 후보만 제거하거나 JEV가 아닌 코드로 다른 수를 고르지 않습니다.
서버는 실패한 후보 ID와 원인을 로그에 남깁니다.

선택한 수의 결과 FEN은 `jev.selectedMove.resultingFen`, 특징은
`jev.selectedMove.features`에 있습니다. 이 데이터는 모델이 생성한 설명이 아니라
서버의 규칙 계산 결과입니다. 확률 목록과 3초 미리보기는 유지합니다.

`.env`에 `JEV_DEBUG=1`을 추가하면 합법 수 개수, 선택 ID, 선택 확률,
선택된 결과 FEN만 출력합니다. 키와 전체 후보 FEN 목록은 출력하지 않습니다.

V1은 현재 FEN과 수 목록을 전달했고, V2는 각 수의 결과 상태까지 전달합니다.
평가 함수, material score, Stockfish, 2-ply 탐색은 없으며 최종 선택은 JEV가 합니다.
후보별 정보가 늘어 API 입력 토큰은 증가합니다. 실제 기력 개선 여부는 별도 비교가 필요합니다.

검증은 `npm test`로 실행합니다. 전체 후보 보존, 원본 FEN/기보 불변,
잡기·앙파상·체크·캐슬링·프로모션, 체크메이트·반복 무승부,
후보 분석 실패 후 재시도, API 옵션의 결과 상태 전달을 검증합니다.
테스트는 실제 API를 호출하지 않습니다.
수동 확인은 서버 재시작 후 New Game → e2-e4 → 우측 결과 FEN/특징/확률 확인 →
3초 후 보드 반영 순서입니다. 실제 API 플레이에는 사용량이 발생합니다.
